# Review 2026-10-29: practices, performance, testability, docs, and the UI on the unit

What this file holds: the findings of the 2026-10-29 review of the whole repository and of the UI on the unit, each
with its fix and its state, so the fixes can be tracked to their merge. What does not belong: the dated findings of a
ride (journal.md), what is built (features.md), what the unit has not shown yet (status.md).

Method: three read-only review passes over main at c0d8368 (the app, the UI and the main loop; the storage, the
recorder and the boot; the tests, the docs and the tools), and a keyed tour of the unit over the dev link (27
screenshots, `tools/dev.py prof` on three screens, cable in, the installed build c0d8368).

State: `[ ]` open, `[x]` merged on main, `[-]` not done on purpose (the reason follows). Severity: H (a ride, data
or the gate at stake), M (wrong or misleading), L (cosmetic or a small gain).

## S. Storage, the recorder and the boot (the golden rule)

Verified clean (file:line in the reviewer's pass): data appended as it goes and a checkpoint at least every 60 s
in the order data, sector 0, size, record (recorder/mod.rs:801, 1273); two records old / new, the newest valid one
by CRC and tag (mod.rs:1250, rec.rs:43); resume at boot from the last checkpoint, torn sector 0 and trailer
rewritten from the record's copies (mod.rs:1408, 1527); the save keeps the ride until the new file is read back
whole (mod.rs:1334), then the mark 0xe5 only (write.rs:708), the link, the record "done"; `deny(indexing_slicing)`
on the recorder and FAT paths, every loop and eMMC wait bounded; nothing below `fat_start` written, each FAT sector
to every copy, FSInfo after, no path names stock's `tmp.fit`; power off checkpoints first (device.rs:230).

- [ ] S1 (H) `recover_from` (recorder/mod.rs:1518-1555, Recording arm): when the ride's entry is gone it takes the
  chain the record names and writes the trailer and sector 0 into it, then trims it to `size`, before anything
  checks the chain is still the ride's. A ride left open and deleted on a computer (or by stock's USB drive after a
  switch) whose clusters a new file took: the next boot overwrites two sectors of that file (a saved ride,
  possibly) and frees its tail. Fix: before any write or trim on a chain no entry names, check `fat.chain` holds
  `size` sectors and its sector 0 equals the record's copy, else `Kept` and nothing touched (as trash.rs does
  with `first_crc`); a cut-at-every-sector test with the chain freed and with it reused.
- [ ] S2 (H) `keep_in_rides` (mod.rs:1151) and `rescue` (mod.rs:737) link a `Handle { first, size }` into
  `\Rustfw\Rides` without checking the chain is allocated and long enough: a chain the computer freed is linked
  onto free clusters, the next ride's `create` takes the same clusters, a cross-link; deleting the phantom later
  frees the new ride. Fix: link only when `fat.chain(d, first)` is Ok, covers `size` and sector 0 matches the
  record's copy; else the record "done" and the chain left lost; tests as S1.
- [ ] S3 (H) `ride_settled()` (app/drive.rs:16) is true after a boot with no RIDE_OPEN marker (a flat battery loses
  it), so the card is lent writable while `ride.rec` may still say "recording" or "saving": the computer can
  delete or fsck the chain the record names, and the next Start acts on it (the door to S1 and S2). Fix: in
  `drive_on`, read the records first (`recover` with `resume_old = false`), or lend read-only until both records
  were read "done" this boot; a simulator test: boot without the marker, a record "recording", USB DRIVE refused
  or read-only.
- [ ] S4 (M) app/stock_data.rs:127-129 clears `trash_check` before `trash::finish` and drops its error, while
  `drive_on` (drive.rs:26) only finishes a delete when `trash_check` is set: a delete cut between `remove` and
  `link`, a card error at the scan's finish, then USB DRIVE: the ride is in neither folder and a computer's fsck
  can free it. Fix: `self.trash_check = trash::finish(..).is_err()` as drive.rs:31 does; a test.
- [ ] S5 (M) `checkpoint` (mod.rs:1267-1285) stores the grown handle back only after `set_size`: when sector 0, the
  size or the record fails, the retry grows again from the old `last`, and the cluster the failed attempt took stays
  EOC, named by nothing (16 KB lost per failed checkpoint on a flaky card, counted used by FSInfo). Fix: store
  `self.file` right after `write_sectors` succeeds; a test that fails the record write once and checks fsck.
- [ ] S6 (H, tests) No cut at every sector for: the save of a stopped ride (`save_as_is` + `trailer_end`,
  mod.rs:1307), GIVE UP SAVE's `rescue` (mod.rs:687), the Start-time handling of an old ride (mod.rs:1008-1074,
  one cut image only in `start_while_the_boot_recovery_is_pending`), an entry removed by a computer with its chain
  freed or reused. Fix: `for cut in 0..total` loops, plain and torn, with `fsck` asserting no cross-link and no
  chain into a free cluster (S1, S2 and S3 bring theirs; the rest here).
- [ ] S7 (M, later) Files created in `\Rustfw` (pages.bin, ble.bin, the barometer's, the trainer's, the trash's
  folders: app/editor.rs:272, phone.rs:514, barometer.rs:193, trainer.rs:338, storage/trash.rs:127) rewrite the
  directory sector that holds `ride.rec`, `Rides`, `Full`, `Activities` and `Discarded`; they run only with the
  ride settled, and the unit's card has reliable writes (BOARD.md 15), so a tear is unlikely but would lose every
  kept ride as a lost chain. A `\Rustfw\State` subfolder changes the card layout (a migration for the owner's
  unit): left for its own change, after the owner decides.
- [ ] S8 (M, later, unit) The stack grows down from the top of DTCM into `.bss` with no MPU guard (main.rs:43-58,
  link.x): an overflow (one happened on 2026-10-24) overwrites `.bss` silently, and reaching unmapped space locks
  the core with no watchdog to reset it. Fix: a no-access MPU region under the stack, thread mode on PSP so the
  fault stacks on MSP and resets. A core-level change: Renode, then a `DIAG_STOP` stage on the unit with the owner
  (AGENTS.md, Tests); `tools/stack_check.py` holds the line until then. The MPU guard locked the core on the unit
  (2026-10-29: with PRIMASK set the fault escalates to HardFault, whose stacking faults); the owner chose a canary
  above .bss checked every pass instead (option C); its unit run is in docs/status.md.
- [-] S9 (L) hw.rs `rd` / `wr` / `wr8` are safe functions over any address, and `peek` may read DTCM a `&mut`
  holds. This is the documented design (AGENTS.md "Safe Rust only": the dev link checks the computer's addresses,
  the primitives stay the only `unsafe`); left as is.

## A. The app, the UI and the main loop: correctness and practices

- [ ] A1 (H) `EDITED = PAGES + 2` (app/settings.rs:158) equals `WORKOUT = PAGES + 2` (settings.rs:100):
  `widgets()` (app/screens.rs:220) matches `WORKOUT` first, so in `Screen::Edit` it returns the workout page's
  boxes instead of the page edited (a touch in the editor then hits the wrong box). Fix: `EDITED = PAGES + 4`, a
  `const { assert!(..) }` that OVERVIEW, COURSE, WORKOUT, CLIMB and EDITED are distinct, a simulator test that
  `widgets()` in the editor equals the page being edited.
- [ ] A2 (M) `500 * (w >> 8 & 0xff) as u16` (settings.rs:521, the 0xc1 power word): the cast binds first, a byte
  over 131 overflows u16 (wraps in release, panics in a debug build), then `clamp` yields an arbitrary W'. Fix:
  `u16::from(byte).saturating_mul(500)`; a unit test with byte 0xff.
- [ ] A3 (L) app/device.rs:145 indexes `LIGHT_TIMEOUTS_S[...]` directly (lines 147 and 307 use `.get()`), on a
  `pub` field: an out-of-range value panics every pass, a reset loop. Fix: `.get(..).copied().unwrap_or(0)`.
- [ ] A4 (L) Hand-written hit tests instead of `Rect` / `inside`: app/screens.rs:406, app/graphs.rs:265,
  app/trainer.rs:76-77, app/input.rs:412. Fix: `inside(bx, x, y)`.
- [ ] A5 (L) app/input.rs:432-433 computes `zoom_at(x, y)` (which rebuilds `widgets()`) in the guard and again
  in the arm; :354-357 `call_choice(i)` twice. Fix: once, before the match or with `if let` in the arm.
- [ ] A6 (L) ui/media.rs:192-197 slices `&s[..i]` / `s[cut..]` (panic formatting in the image, text.rs:210).
  Fix: `s.get(..).unwrap_or("")`.
- [ ] A7 (L, docs) lib.rs:67 `Board::delay_ms` says "Busy wait." but main.rs:143 sleeps on SysTick and WFI;
  app/pass.rs:7-8 and 11-12 repeat one sentence in the doc and the body. Fix: the comments.
- [ ] A8 (M, later) main.rs:1798-1943, the 145-line loop body, holds device policy (the sleep slice, the wake
  reasons, unplug means reset, the awake permille): untestable on the host, against "logic belongs in the
  library". Fix: a pure `Sleep` struct in the library fed with cycles, edge, done and io, tested on the host. A
  change to the loop debugged on the unit (the 2026-10-24 stalled-loop class): its own session with the owner.
- [ ] A9 (L, later) `App` keeps loose flags and anonymous tuples (`climb: (bool, usize, Option<(u32, bool)>)`,
  `ahead_us: (u32, u32, u32)`, `ride_started: ((u16, u8, u8), (u8, u8))`; the baro, battery, touch, map and
  powercal field groups) where app/groups.rs has the pattern. Fix: name the three tuples' fields in small structs
  first; the groups as they are next touched.

## P. Performance in the loop

- [ ] P1 (M) `update_page` (app/screens.rs:564-624, app/fields.rs:129-190) runs every pass: `widgets()` built two
  or three times, `route()` twice per map box, every value box's text, colour and bar formatted, while the live
  values change once a second. On the unit: `draw` 125 to 138 us every pass with 0 px/s sent (E1). Fix: skip the
  value boxes unless a second ticked, a live value or the screen changed; `widgets()` and `route()` once per call.
  Measure with `dev.py prof` before and after.
- [ ] P2 (M) `update_graph` (app/graphs.rs:115-126, 221-229, 274-283) calls `graph_now` every pass: for `Plot::Alt`
  that averages up to 512 whole-ride bars (`alt_scale`) 20 times a second; `workout_now` rescans the steps' total,
  `profile_now` runs `climb_now`, per pass. Fix: return early when the history length and the inputs are
  unchanged; cache the Alt scale and the workout total until they change.
- [ ] P3 (M) `redraw_top` (screens.rs:439-447, from `unbanner`) calls `draw_screen` whole with a row-clipped
  `Panel`: every graph column, profile, workout bar and the TODAY card are computed then discarded on each banner
  dismissal (a cue, an alert, a lap, during a ride). Fix: `draw_screen` / `draw_widget` skip a box outside
  `clip()`.
- [ ] P4 (L) `update_menu_rows` (app/menus.rs:567-575, ui/mod.rs:527-543) repaints a whole 240 x 43 row when only
  its value changed (the live SENSORS, GPS, BUILT IN menus, the scan's progress). Fix: an unselected row whose
  label and colour are unchanged redraws its value box only (`draw_in` clears its own box).
- [ ] P5 (L) Every BLE advertisement sets `list_dirty` (app/pass.rs:98, app/radio.rs:123) and `draw_list`
  (ui/mod.rs:251-284) repaints every row once a second for 10 s per scan. Fix: a per-row fingerprint (name,
  maker or address, rssi) as `menu_shown` does; only the rows that differ.
- [ ] P6 (L) ui/text.rs:141-202: two divisions per pixel (`px / k`, `py / k`) and a 16-entry palette rebuilt (48
  divisions) at every `draw`, `draw_clipped` and `redraw_char`. Fix: step the source x / y with counters; the
  palette only for the levels used, or cached by (fg, bg); the font sheet and pixel-cell tests must not change.
- [-] P7 (L) `draw_cog` computes its coverage per pixel on each date draw (625 px): a few thousand operations
  when a screen opens; not worth a table.
- [-] P8 (L) `poll_nrf` zeroes 192 bytes of stack buffers each pass (app/radio.rs:115, 187): about 4 KB/s of
  memset, negligible; left.
- [ ] P9 (L) `light` runs twice a pass on the unit (42 calls/s, 28 us): E2.

## E. The UI on the unit

Measured (`dev.py prof`, 5 s windows, cable in, idle, no ride): overview 21.2 passes/s, 1.10 % awake; ride page 1
1.12 %; menu 0.78 %. The three largest sections idle: `radio` 0.26 % (42 calls/s, 62 us), `draw` 0.27 % on the
overview and 0.29 % on a ride page (125 to 138 us every pass, with 0 px/s sent to the panel), `light` 0.12 %
(42 calls/s, 28 us).

- [ ] E1 (M, perf) `draw` runs 125 us every pass with nothing to paint: `update_page` rebuilds and compares every
  field's text 21 times a second while no value changed. Fix: run the page update only when something it draws can
  have changed (the second tick, a sensor or phone event, an input), else skip the pass. Measure before and after
  with `dev.py prof` (expected: `draw` near zero idle, awake about 0.8 % on the overview).
- [ ] E2 (L, perf) `light` runs twice a pass (42 calls/s) at 28 us: the ambient read or the level computation is not
  gated to the backlight's own time-out resolution. Fix: once a pass, and only every N passes while the level is
  held. Measure with `dev.py prof`.
- [ ] E3 (M) A banner over the overview ("NO PHONE" after a long Lap with no phone) covers 44 px but the date line
  ends lower, so a 6 px sliver of "THU 29 OCT" stays visible under the banner (ui/mod.rs `BANNER_H` 44,
  ui/overview.rs `DATE_Y + DATE_H`). Fix: `BANNER_H` covers the date line (keep the test at ui/mod.rs:601, check
  the simulator screenshot of a banner over the overview and over a ride page).
- [ ] E4 (L) The last screen of a menu longer than one screen shows one lone row (SYSTEM: "AUTO OFF" alone at the
  top, six empty slots): `menu::first_shown` scrolls by whole screens. Fix: the last screen starts at
  `total - MENU_ROWS` so it is full (moving within a screen still redraws two rows); a test on a 7-row menu.
- [ ] E5 (L) Units are written two ways: "TRG 100W" on the ride page, "FTP 265 W" and "WEIGHT 78 KG" in the menus.
  Fix: one rule (a space before the unit everywhere), in ui/fields.rs and app/fields.rs where the target is written.
- [ ] E6 (L) The notices row cuts a notification mid-word with no cue ("Remote control e"). Fix: cut at the last
  space that fits (ui/overview.rs `draw_notices`); the full text stays one tap away.
- [ ] E7 (L, doc) Page (Next) on the last ride page wraps to the first page and never returns to the overview (Back
  does); the comment on `App::input` (app/input.rs) says "through the ride pages and back". Fix: the comment.
- [-] E8 (L) The course list keeps a long name whole and drops the unit, then the distance ("FRANGE VERTE 22.9",
  "QUAIX RACHAIS" with no distance): app/courses.rs `course_row` does it on purpose. Left as designed; the owner may
  prefer the distance kept and the name cut.
- [-] E9 (L) Before a ride, KJ and RPM read "0" where AVG W, NP and HR read "--". A sum is 0 and a mean is unknown:
  consistent with itself, left as is.

Tour side effect: the keyed tour selected the last SYSTEM row, which cycled AUTO OFF from 5 MIN to 10 MIN and
wrote `\Rustfw\settings.bin` once (the firmware's own file, one sector). Set it back in SYSTEM > AUTO OFF (four
presses: 30, 60, OFF, 5).

## D. Tests, docs and tools

- [ ] D1 (H, tool) `tools/dev.py get` takes any answer shorter than 4096 bytes as the end of the file, and a cut hex
  answer raises an uncaught ValueError: a dropped link writes a truncated copy with no error. Fix: compare the byte
  count against the listing's size (and a CRC where the link gives one), catch the decode error, exit non-zero.
- [ ] D2 (M, test) Fuzz tests with no reach assertion (they pass if the decoder refuses everything):
  `phone_link_events` (src/sim/fuzz.rs:1145), `lz4_blocks` (:1072), `heart_rate_beats` (:113),
  `usb_drive_commands` (:1103, CSW shape only). Fix: structured inputs where the random ones never parse, and a
  count over the seeds asserted above zero for each path reached (parsed notifications, data sources completed,
  Stored records, LZ4 tiles decoded, beats pushed, READ10 / WRITE10 / refused opcode / damaged CBW).
- [ ] D3 (M, test) The recovery record read at boot (`Rec::from_sector`, src/storage/recorder/rec.rs:42 and
  src/storage/trash.rs:88) has only hand-picked damage tests. Fix: a fuzz that flips bytes of valid records and
  asserts a refusal or the exact record back, counting both outcomes.
- [ ] D4 (M, test) Screens `Quick`, `PowerCal`, `RampResult`, `About` and `Notif` are not reached by the random
  menu-and-key fuzz (`menu_touch_and_keys`, `menu_tree_by_chance`). Fix: open them in the random walk and count.
- [ ] D5 (L, test) Raw samples with no fuzz: `battery::millivolts` / `percent` (src/drivers/battery.rs) and the
  ambient light and barometer raw values (src/drivers/ambient.rs). Fix: one fuzz over all raw values asserting the
  outputs stay in range.
- [ ] D6 (M, test) Wall-clock asserts (`elapsed() < 300 ms`, src/nav/course/mod.rs about line 1109) and timing
  prints in src/nav/course/cues.rs and src/nav/climbs_ahead.rs: flaky on a busy machine, and they pass whatever the
  cost. Fix: assert a step or operation count, or drop the timing assert and keep the functional checks.
- [ ] D7 (M, docs) README key figures (lines 46 to 48) hold the 2026-10-27 numbers (1.55 / 1.32 / 1.82 %) while
  docs/status.md has the 2026-10-29 profiler run (1.51 % idle, 1.46 and 1.37 % on ride pages, 2.69 % menu); the
  README status paragraph (line 36, "2026-10-27") predates the settings file, themes, power match and the
  profiler. Fix: the 2026-10-29 numbers and date, the paragraph updated.
- [ ] D8 (M, docs) Three page-layout counts: README "fourteen", status.md "eleven", `LAYOUTS: [Layout; 16]`
  (src/ui/fields.rs:402). Fix: drop the count from both docs.
- [ ] D9 (M, docs) "Van Rysel D500" names the owner's trainer in docs/status.md (lines 60, 84, 129, 135),
  docs/layout.md:136 and src/drivers/fecble.rs (lines 2, 13); the owner's trainer is a D900. Fix: D900 where it is
  the owner's, the D500 kept only where the text is about that model.
- [ ] D10 (L, docs) Cargo.toml `description` says "shows the RTC time". Fix: describe the firmware as it is.
- [ ] D11 (L, docs) AGENTS.md says `cargo deny` "checks duplicates" but deny.toml has `multiple-versions = "warn"`
  (Cargo.lock holds `nb` 0.1 and 1.0). Fix: say "warns on duplicates" in AGENTS.md.
- [ ] D12 (M, gate) check.sh: `stack_check.py`, `pack.py` and `numbers.py` run without `-I` (the others use it);
  `tools/ign_pack.py selftest` exists and is not run; a missing Renode, fitdecode or cargo-deny is skipped with an
  echo and nothing at the end says so. Fix: `-I` everywhere it works, the ign_pack selftest added (and to the

- [ ] D14 (L, gate) src/ui/fonts.rs is generated but nothing checks it was not edited by hand. Fix: a check.sh step

- [-] D15 (L, test) `App::start(&mut sim, None)` is repeated 194 times in the simulator tests. A `Sim::app()`
