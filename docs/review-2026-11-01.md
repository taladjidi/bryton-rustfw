# Review 2026-11-01: tests, correctness, duplication, dead code, performance

What this file holds: the findings of the night audit of 2026-10-31 to 11-01 (main at 83b0670), each with its fix
branch and its state, so the fixes can be tracked to their merge. What does not belong: what is built (features.md),
what the unit has not shown yet (status.md), the previous audit (review-2026-10-31.md, whose fixed items are not
repeated here).

Method:
- tools: `cargo llvm-cov` on the host tests (1 390 passed, 10 ignored; 96.8 % of lines, 95.0 % of regions; 26 min
  instrumented against about 20 s plain), jscpd over src and tools (130 clones, 260 duplicated lines outside the
  simulator), `llvm-nm --size-sort` on the release ELF, `cargo mutants` on src/storage/recorder/rec.rs, copies.rs,
  trash.rs and fat/write.rs (the files the morning audit never mutated), clippy pedantic counts on the library;
- eight read-only review passes, each on its own area: the storage write path and the power-cut tests (Opus), the
  radio / USB parsers, the test strategy, the board, boot and unsafe code (Opus), per-pass performance, the training
  and navigation maths, app / ui structure and dead code, the tools and the gate, the file readers;
- two findings proven by probe tests before any fix (1 and 2 below fail on 83b0670).
- The unit was not connected (the owner asleep): what needs it is listed under each finding and in status.md.

State: `[ ]` open, `[x]` merged on main, `[-]` not done on purpose (the reason follows). Severity: H (a ride, data, the
unit or the gate at stake), M (wrong, a measured cost, or a rule broken), L (small). Branch: the fix branch's label.

**Verdict:** nothing loses a ride in progress; the recording path holds. Fix first: the HISTORY delete on a full card
(1), the recovery tool's device pick and hash check (41, 42), the dev link's commands that cut a ride (17, 18), and
the test strategy's blind spots (nothing independent of this code checks what it writes: 4, 30; the main loop and
main.rs untested: 31, 32).
